# GUI Tab 布局与表情排序重构规格

日期：2026-07-30
状态：已实现

## 背景

当前 GUI 将账号选择、获取预览、导出设置、高级选项和表情网格纵向堆叠在同一页面。默认窗口为 800×600，获取表情后仍需要向下滚动才能看到预览；同时，数据库返回的表情按较早到较新的顺序展示，最新添加的表情位于列表末尾。

本次重构通过压缩账号区域、引入功能 Tab 和增加排序偏好，让表情预览成为首要界面，同时保持现有账号发现、URL 获取和图片下载机制不变。

## 目标

1. 删除页面顶部重复的应用名称。
2. 压缩账号区域，使正常状态下的默认窗口尽可能露出第一排表情图片。
3. 将账号下方功能拆分为“表情预览”“导出”“高级设置”三个 Tab。
4. 默认按最新添加在前展示，并让预览顺序与导出顺序保持一致。
5. 让未完成导出记录携带排序方式，避免续跑时混用不同顺序。
6. 保持获取或导出任务运行时可以浏览其他 Tab。

## 非目标

- 不实现跨应用重启的预览恢复。
- 不新增统一 `targetId` URL 缓存。
- 不改变现有微信 3.x/4.x 的账号发现和 URL 提取流程。
- 不改变现有分组、断点续跑和自动打开目录设置的持久化行为。
- 不实现真正的新增/删除表情增量同步。

应用冷启动后，预览数据仍为空，用户需要点击“获取并预览”。微信 4.x 已有缓存 key 时继续沿用当前的快速离线解析流程。

## 页面结构

### 顶部与账号区域

- 删除页面顶部“导出微信表情包”标题。
- 删除“账号”标题。
- 账号选择框占据主要宽度，“刷新”按钮位于其右侧。
- 单账号仍使用不可编辑的账号选择展示，多账号使用下拉选择。
- 删除独立的“该账号最后更新时间”信息提示。
- 最后更新时间继续包含在账号选项文案中。
- 账号扫描失败、未发现账号和目录权限异常仍在账号区域显示 Alert。

### Tab

账号区域下方固定显示：

1. 表情预览
2. 导出
3. 高级设置

每次应用启动默认选中“表情预览”，不记忆上次停留的 Tab。

## 表情预览 Tab

包含：

- “获取并预览”或“重新获取”操作。
- 微信未退出提示和“重新检查”操作。
- 微信 4.x 获取 key 的步骤条。
- URL 解析状态、进度和错误。
- 表情数量、分页器和图片网格。
- 单张表情的复制链接、打开链接和大图预览操作。

获取任务运行时允许切换到其他 Tab；预览 Tab 标题旁显示小型加载状态。

本次不增加预览 URL 的跨重启缓存。应用重启后，即使后端存在 `emoticon_urls_<wxid>.txt`，GUI 也不会自动读取并恢复图片列表。

## 导出 Tab

包含：

- 导出分组设置：每 50 张、不分组、自定义数量。
- 断点续跑开关。
- 导出完成后自动打开目录开关。
- 开始导出、继续上次导出和取消导出操作。
- 导出进度以及成功、跳过、失败统计。
- 上次导出目录和打开目录操作。

尚未获取表情时，Tab 保持可点击，面板显示空状态和“去获取”按钮；点击后切换到“表情预览”Tab。

导出任务运行时允许切换 Tab；导出 Tab 标题旁显示小型加载状态。会影响当前任务的设置保持禁用。

## 高级设置 Tab

包含：

- 表情排序设置。
- WeChat.app 路径及选择操作。
- 当前账号的 db key、URL 文件和日志调试产物。
- 复制、打开调试产物的操作。
- 清除当前账号缓存。

原“展开/收起高级选项”按钮不再保留，高级内容由 Tab 直接控制显示。

## 表情排序

排序值定义为：

```ts
type EmojiSortOrder = "newest-first" | "oldest-first";
```

用户文案：

- 最新添加在前（默认）
- 最早添加在前

行为规则：

- 排序作为全局应用偏好写入 `localStorage`。
- 未保存过排序时使用 `newest-first`。
- `newest-first` 将当前数据库返回顺序反转。
- `oldest-first` 保持当前数据库返回顺序。
- 排序同时影响预览和导出，保证所见即所得。
- 切换排序后立即重排当前预览，不重新解析数据库。
- 切换排序后将预览页码重置为第 1 页。
- 导出进行中禁止修改排序。

排序应从原始 URL 列表派生，不应原地反转或覆盖原始列表，以避免反复切换时顺序漂移。

## 未完成导出记录

现有未完成记录：

```ts
type IncompleteExport = {
  dirName: string;
  groupSize: number;
};
```

调整为：

```ts
type IncompleteExport = {
  dirName: string;
  groupSize: number;
  sortOrder: EmojiSortOrder;
};
```

规则：

- 新建导出时保存当时的 `sortOrder`。
- 历史记录缺少 `sortOrder` 时，按旧版本行为推断为 `oldest-first`。
- 继续导出前比较当前排序与记录排序。
- 两者一致时直接继续。
- 两者不一致时显示确认对话框，提供：
  1. 按上次排序继续导出：临时使用记录中的排序，保证原目录结构一致。
  2. 按当前排序开始新的导出：创建新的时间戳目录，不修改旧目录。

选择“按上次排序继续”不应覆盖用户的全局排序偏好；它只影响本次续跑任务。

## 状态与交互约束

- 切换 Tab 不得取消正在进行的获取或导出任务。
- 切换账号继续沿用现有行为：清空当前内存中的 URL 和预览数据，重置获取状态。
- 获取期间禁止会影响获取流程的账号、微信路径和缓存操作。
- 导出期间禁止账号切换、排序切换、导出设置修改和缓存清理。
- 导出完成/取消对话框保持现有行为。
- 账号级错误显示在账号区域；获取级错误显示在预览 Tab；导出级状态显示在导出 Tab。

## 验收标准

1. 页面不再显示顶部“导出微信表情包”标题和“账号”标题。
2. 账号选择框与刷新按钮在同一行，不再显示独立最后更新时间 Alert。
3. 默认打开“表情预览”Tab，刷新应用后仍默认打开该 Tab。
4. 正常获取表情后，默认窗口能看到预览标题和至少部分第一排图片。
5. 获取、导出和高级设置控件分别只出现在对应 Tab。
6. 未获取表情时可以进入导出 Tab，并能通过“去获取”返回预览 Tab。
7. 获取或导出运行中可以切换 Tab，任务不被中断，对应 Tab 显示加载状态。
8. 默认排序为“最新添加在前”，刷新应用后排序偏好仍然存在。
9. 切换排序立即重排预览并返回第 1 页，不触发数据库重新解析。
10. 新导出顺序与当前预览顺序一致。
11. 未完成导出记录包含排序方式；旧记录按 `oldest-first` 迁移。
12. 续跑排序不一致时出现选择对话框，两种路径均不会混写错误顺序。
13. 微信 3.x 和 4.x 共用相同 UI、排序与导出逻辑，不出现版本专属 Tab 布局。

## 测试要求

至少覆盖以下 GUI 测试：

- 默认 Tab 和三个 Tab 的内容边界。
- 删除标题、账号区压缩后的关键元素。
- 未获取状态下从导出 Tab 跳转到预览。
- 默认倒序、切换正序以及页码重置。
- 排序偏好的读取和写入。
- 获取、导出期间切换 Tab 不影响任务。
- 新未完成记录写入 `sortOrder`。
- 旧记录迁移为 `oldest-first`。
- 续跑排序一致时直接继续。
- 续跑排序不一致时的两个对话框分支。
- 原有无账号、微信未退出、无效路径、成功预览、缓存清理、取消与续跑场景继续通过。
