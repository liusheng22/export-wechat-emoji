# 启动预览恢复、自动刷新、导出偏好与预览交互规格

日期：2026-07-30
状态：已实现

## 背景

现有 GUI 已完成“表情预览 / 导出 / 高级设置”Tab 和表情排序重构，但预览 URL 与部分界面状态仍只存在于当前 React 进程中：

- 应用重启或切换账号后会清空预览，即使磁盘上已经有 URL 产物也必须再次点击“获取并预览”。
- 微信 4.x 的 db key、URL 文件和日志入口依赖本次运行的 `lastDumpResult`，重启后高级设置无法直接定位已有调试产物；微信 3.x 解析结果没有统一的账号缓存。
- 导出分组、断点续跑和导出后自动打开目录均未持久化。
- 预览网格被放在额外的 Section 框中，标题与“表情预览”Tab 重复；图片点击只负责查看大图，复制链接和打开链接占据了每个 Item 的额外空间。
- 获取任务开始后会清空 URL，按钮虽然已禁用，文案却退回“一键获取并预览”，无法表达实际仍在获取。

本规格在 `2026-07-30-gui-tabs-and-emoji-ordering.md` 的基础上继续演进。本文明确覆盖并替代该规格中的以下旧约束：不做跨重启预览恢复、不新增统一账号 URL 缓存、切换账号只清空预览，以及旧版微信高级设置不展示 URL 产物。其余 Tab、排序和导出顺序约束保持有效。

## 目标

1. 用统一、稳定的 `targetId` 标识微信 3.x 和 4.x 账号，并按账号读写 URL 缓存与调试产物。
2. 冷启动或切换账号后优先恢复该账号的缓存预览；若当前账号存在 db key，再自动尝试刷新一次当前账号。
3. 刷新期间保留已恢复的可用预览，并让按钮禁用状态与加载文案一致。
4. 持久化全部导出设置，重启后按容错后的上次值恢复。
5. 压缩预览区布局；点击表情图片时下载并复制原图文件，使用小图标承载查看大图和打开链接操作。
6. 让复制和导出共享二进制下载结果，避免同一表情被重复请求。

## 非目标

- 不实现表情数据库的增量同步；自动刷新仍是当前账号 URL 列表的完整重算与原子替换。
- 不跨应用重启持久化表情图片二进制；只持久化原始 URL 列表与调试产物。
- 不自动为没有 db key 的微信 4.x 账号启动注入、拉起微信或要求用户退出微信。
- 不改变现有排序语义、导出文件命名、未完成导出记录或排序冲突处理。
- 不自动刷新微信 3.x；3.x 没有 db key，启动/切账号时只恢复 URL 缓存，手动“重新获取”仍从 `fav.archive` 解析。

## 统一账号标识

### `targetId`

所有账号级状态必须以同一个规范化身份为入口，不允许部分代码使用 `wxid`、部分代码使用选择框下标或显示文案：

```ts
type EmojiTarget =
  | { kind: "legacy"; versionDir: string; userDir: string }
  | { kind: "v4"; wxidDir: string };

type TargetId = string;

function targetIdOf(target: EmojiTarget): TargetId {
  return encodeEmojiTarget(target);
}
```

`TargetId` 的规范值沿用现有 `encodeEmojiTarget` 结果：

- 微信 3.x：`legacy|<versionDir>|<userDir>`
- 微信 4.x：`v4|<wxidDir>`

这保证已有的 `wxemoticon_last_target`、最近导出目录和未完成导出记录不需要改变账号语义。显示名称、列表顺序、数据库更新时间和 React 渲染下标都不能参与身份计算。

`wxidDir` 作为现有微信 4.x 账号标识原样参与 `targetId` 计算。预览缓存使用 `localStorage` 键保存；读回时仍必须校验记录内的完整 `targetId`。

### 账号级键

以下状态统一使用 `targetId`：

- 当前选择与上次选择；
- URL 缓存与调试产物定位；
- db key 存在性检查；
- 清除当前账号缓存；
- 自动刷新任务的归属与过期结果判断；
- 最近导出目录、未完成导出记录。

刷新账号列表后，即使 `EmojiTargetMeta` 对象被重建，只要 `targetId` 不变就视为同一账号。

## URL 缓存与调试产物

### 存储键与格式

GUI 的权威预览缓存写入：

```text
wxemoticon_preview_cache|<targetId>
```

值使用以下 V1 schema：

```ts
type PreviewCacheV1 = {
  version: 1;
  targetId: string;
  urls: string[];
  updatedAt: string; // ISO 8601
  artifacts?: AutoDumpUrlsResult; // 仅 4.x 成功获取后存在
};
```

规则如下：

- `urls` 保存数据库或 archive 的原始顺序；排序仅在 React 派生层进行，不把“最新在前”的结果写回缓存。
- 读取时要求 `urls` 非空且每项均为 `http://` 或 `https://` URL；保留相对顺序和重复项。
- 版本不支持、`targetId` 不匹配、JSON 损坏或 URL 非法时整条缓存安全失效，不恢复到界面。
- 微信 3.x 每次手动解析成功后写入账号缓存，因此下次启动可以恢复。
- 微信 4.x 自动或手动刷新成功后写入 URL，并保存本次 `AutoDumpUrlsResult` 作为调试产物元数据。
- `localStorage` 读写失败时保留当前内存预览，不阻断获取、预览或导出。
- 图片二进制不写入 `localStorage`；当前进程继续使用共享 LRU，同时将点击复制过的原格式文件写入应用缓存目录，供后续 session 复用。

### 现有 4.x 文件兼容

现有 Rust 获取流程继续写入账号后缀的 db key、URL 与日志文件，供 CLI 和高级设置使用。GUI 的兼容规则为：

- 只用 `emoticon_dbkey_<wxidDir>.txt` 判断当前 4.x 账号是否有 key，从而决定是否自动刷新。
- 不使用无账号归属的 `emoticon_dbkey.txt` 猜测当前账号，避免多账号串 key。
- URL 预览只从统一 `targetId` 缓存恢复；旧的无元数据 URL 文件不直接迁移到预览缓存。
- 清理 4.x 当前账号时，同时清理当前账号明确带后缀的兼容文件；不删除共享旧文件和其他账号文件。

### 高级设置调试工具

高级设置不再只依赖本次 React 生命周期内的 `lastDumpResult`。选择账号后从该账号的预览缓存恢复调试元数据：

- 3.x 存在有效 URL 缓存时显示缓存条数和“不生成 db key”的说明；3.x 缓存位于应用本地，不提供虚假的文件路径操作。
- 4.x 缓存含调试元数据时，恢复“复制 db key”“打开 db key 文件”“打开 URL 列表文件”“打开日志目录”及路径复制操作。
- 应用重启并恢复 4.x 预览后，上次成功获取生成的调试入口立即可用，不要求再次点击获取。
- 切换账号时调试入口与路径同步切换，不得残留上一个账号的 `lastDumpResult`。
- “清除当前账号缓存”对 3.x 和 4.x 都可用，只删除当前 `targetId` 的 localStorage 记录；4.x 同时清除当前账号明确归属的兼容 key/URL 产物。不得删除其他账号或无从确认归属的共享兼容文件。
- 清除成功后清空当前账号的内存预览和调试入口。正在获取、复制或导出时继续禁用清理。

## 启动恢复与自动刷新

### 触发时机

以下两种情况执行同一套 `activateTarget(targetId)` 流程：

1. 冷启动完成账号扫描并确定初始账号后；
2. 用户切换到另一个账号后。

刷新账号列表但仍选中同一 `targetId` 时不得重复触发自动刷新；React Strict Mode 的重复 effect 也必须被去重。每次真正切换 `targetId` 时生成新的激活代次或取消令牌，旧账号晚到的缓存读取、进度事件和刷新结果一律丢弃。

### 固定时序

`activateTarget` 必须按以下顺序执行：

1. 重置上一个账号的错误、页码和调试视图，并把当前任务归属切到新 `targetId`。
2. 读取并校验当前账号 URL 缓存。
3. 若缓存有效，立即设置 `rawUrls`、按当前排序派生预览并回到第 1 页；用户无需等待数据库刷新即可浏览和导出。
4. 解析当前账号调试产物，更新高级设置入口。
5. 仅对当前 v4 账号检查其账号级 db key。若存在 key，自动发起一次离线刷新；若无 key，流程到此结束，等待用户手动获取。
6. 3.x 不检查 key、不自动解析 archive，只展示第 3 步恢复的缓存或空状态。

不得枚举并刷新全部账号，也不得因为 A 账号有 key 而刷新 B 账号。

### 自动刷新结果

- 自动刷新与手动“重新获取”共用同一获取管线和每账号并发锁，同一 `targetId` 同时最多一个任务。
- 有缓存时，刷新开始不得清空 `rawUrls`；预览、分页和导出仍使用已恢复数据，直到新结果完整成功。
- 刷新成功后原子写入缓存，再一次性替换当前账号 `rawUrls`，沿用当前排序并将页码重置到第 1 页。
- 自动刷新失败但已有缓存时，保留缓存预览和可导出状态，以非阻塞警告提示“已显示缓存，自动刷新失败，可手动重试”；不能切换到遮蔽预览的全页错误状态。
- 自动刷新失败且没有缓存时显示现有获取错误状态。
- 自动刷新发现 key 失效时不自动进入需要退出微信/注入的新 key 流程；保留缓存并提示用户手动重新获取。只有明确的用户操作可以触发现有的新 key 获取流程。
- 任务期间允许切换 Tab；切换账号仍受现有获取中禁用规则约束。组件卸载或账号变化后不得写入旧任务结果。

### 获取按钮状态与文案

按钮文案由显式的任务意图和加载状态决定，不能通过 `rawUrls.length` 间接推断：

| 状态 | 文案 | 是否禁用 |
| --- | --- | --- |
| 无预览、空闲 | 一键获取并预览 | 否（满足现有前置条件时） |
| 有预览、空闲 | 重新获取 | 否 |
| 首次手动获取中 | 正在获取… | 是 |
| 自动刷新或手动重新获取中 | 正在重新获取… | 是 |

加载按钮继续显示进度图标。尤其是自动刷新和保留缓存的手动刷新期间，按钮不得短暂显示“一键获取并预览”。Tab 上的加载状态与按钮使用同一任务状态源。

## 导出设置持久化

### 存储 schema

导出设置是全局应用偏好，不按账号区分。统一写入 localStorage key `wxemoticon_export_settings`：

```ts
type PersistedExportSettingsV1 = {
  version: 1;
  groupMode: "recommended" | "none" | "custom";
  customGroupSize: number;
  resume: boolean;
  autoOpen: boolean;
};
```

默认值与当前界面一致：

```ts
{
  version: 1,
  groupMode: "recommended",
  customGroupSize: 50,
  resume: true,
  autoOpen: true
}
```

### 读取、校验与写入

- React 首次初始化时同步读取一次，避免先用默认值渲染后由 effect 覆盖用户设置，也避免默认 effect 抢先覆盖存储。
- JSON 无法解析、顶层不是对象或版本不支持时使用全部默认值，应用必须继续启动。
- 对受支持版本逐字段校验，单个坏字段只回退该字段，不丢弃其他有效字段。
- `groupMode` 只接受三个枚举值。
- `customGroupSize` 只接受有限的正整数；浮点数向下取整，非有限值、小于 1 或超出安全整数范围时回退 50。
- `resume` 和 `autoOpen` 只接受 boolean，不做字符串真值转换。
- 读取并规范化后写回完整 V1 数据，完成坏字段自愈和未来迁移落盘。
- 任一设置变化后写入完整对象；localStorage 读写抛错时保留当前内存值，不阻断预览或导出。
- 导出开始时继续快照当时的有效设置；导出中控件禁用，任务不受随后持久化写入影响。

必须持久化的四项为：分组方式、自定义分组大小、是否启用断点续跑、导出完成后是否自动打开目录。表情排序继续使用其现有独立 key，不并入本 schema。

## 预览布局与 Item 交互

### 布局

- 删除 Tab 容器下方单独包裹网格的 `Paper/Section`；账号、Tabs、当前预览操作区和预览网格处于同一个上方容器中。
- 删除“`n` 个表情包预览”标题，避免与“表情预览”Tab 重复。
- 多页时仍保留“第 x-y 个 / 共 n 个”和分页器；单页不额外增加数量标题。
- 空状态、获取错误、微信未退出提示和步骤条仍属于预览 Tab，切换到其他 Tab 时不显示预览网格。

### 点击图片：下载并复制原图文件

点击表情图片主体执行：

1. 通过现有 stodownload 候选 URL 与 fallback 逻辑获取二进制。
2. 按现有优先级综合响应 `Content-Type`、文件魔数和实际使用 URL 判断 `gif` / `png` / `webp` / `jpg`。
3. 将原格式二进制原子写入 Tauri `appCacheDir/emoji-files/v1`，并把缓存文件的 `NSURL` 写入系统剪切板；复制的是原图文件而不是 URL 文本，格式与扩展名必须保持一致。
4. 成功提示“已复制原图文件”，失败显示可恢复的提示并允许再次点击。

单个 Item 获取中显示局部 loading 覆盖层并防止重复点击，不阻塞其他表情、分页或 Tab。没有识别出受支持图片格式、下载失败或剪切板拒绝写入时不得报告成功，也不得污染已有剪切板。

### 大图与链接图标

每个 Item 右下角叠放两个紧凑图标按钮：

- 放大镜加号：只打开现有大图查看器，不触发下载复制。
- 链接：用系统默认方式打开该 Item 当前有效的图片 URL，不触发下载复制。

图标点击必须阻止冒泡，不能同时触发图片主体复制。两个图标都要有 Tooltip、可聚焦按钮和明确的无障碍名称（“查看大图”“打开图片链接”）。移除 Item 下方“复制链接”和“打开链接”文字按钮；不再提供复制链接入口。

键盘操作与鼠标一致：图片主体是可聚焦控件，Enter/Space 触发下载复制；图标各自可独立操作。

### 二进制资源复用

新增共享的表情二进制获取层，图片复制和导出都必须调用它，不能各自直接调用 `fetchBinaryWithFallback`：

- 缓存键使用规范化的原始表情 URL；同一 Item 的候选后缀 URL 归为同一个键。
- 对进行中的请求缓存 Promise，使并发的复制/导出只发起一次网络请求。
- 成功结果至少包含 `buffer`、`usedUrl`、`contentType` 和检测后的扩展名，并放入有界的进程内 LRU 缓存；建议上限为 64 项或 64 MiB，任一先到即逐出最旧项。
- 下载失败必须移除 in-flight 项，允许下一次重试；不得永久缓存失败。
- 调用方不能修改共享 `ArrayBuffer`；写文件或剪切板时使用只读视图或复制。
- 账号切换不要求清空二进制缓存，因为键是完整 URL；清除账号 URL 缓存也不承担进程级图片缓存清理语义。
- 预览 `<img>` 自身仍可使用 WebView HTTP 缓存；本要求至少保证显式二进制下载在重复点击、并发点击与后续导出之间复用。
- 点击复制还需先按规范化 URL 的稳定哈希检查 `appCacheDir/emoji-files/v1`；命中时不再下载或传输图片字节，直接复制缓存文件 URL。
- 磁盘缓存跨应用 session 保留，使用真实扩展名，并按最旧修改时间清理到不超过 512 MiB；系统仍可按平台缓存语义回收整个目录。

## 状态与并发约束

- `targetId`、已显示数据的来源（缓存/本次刷新）和获取任务归属必须可区分，不能继续只用一个全局 `lastDumpResult` 表达。
- 所有异步完成回调在提交状态前校验当前激活代次和 `targetId`。
- 自动刷新不改变当前 Tab，也不弹出要求退出微信的阻塞对话框。
- 恢复缓存后即允许导出；自动刷新成功替换列表前，不得把一次导出任务中途切换到新 URL。导出继续使用启动时的 URL 快照。
- 排序变化只重排当前 `rawUrls`；读取缓存、自动刷新和资源复用均不改变现有排序偏好。
- 清理缓存、账号切换、获取和导出沿用现有互斥禁用规则；单张图片复制不应全局禁用界面。

## 验收标准

1. 已成功获取过的 3.x 和 4.x 账号在应用重启后自动显示各自缓存表情，无需点击获取。
2. 多账号之间的 URL、key、日志和高级设置入口严格按 `targetId` 隔离。
3. 启动或切换到有 key 的 4.x 当前账号时，在恢复缓存后只自动刷新该账号一次；其他账号没有后台获取。
4. 无 key 的 4.x 和所有 3.x 账号不会自动启动获取；仍可恢复各自已有 URL 缓存。
5. 自动刷新失败时已恢复的预览和导出能力不丢失，并出现非阻塞警告。
6. 自动或手动重新获取期间按钮禁用且显示“正在重新获取…”，首次获取显示“正在获取…”，不会跳回“一键获取并预览”。
7. 切换账号或旧任务晚到时，不会把前一个账号的 URL、错误、进度或调试路径写入当前界面。
8. 应用重启后分组方式、自定义分组大小、断点续跑开关和自动打开目录开关均恢复为上次值。
9. 导出设置存储损坏或部分字段非法时应用正常启动，合法字段保留、非法字段按规范回退。
10. 预览网格不再有独立 Section 外框，也不显示“n 个表情包预览”重复标题。
11. 点击图片主体会下载并把相应格式的原图文件复制到剪切板，不会复制远程 URL；成功与失败反馈准确。
12. 放大镜图标只查看大图，链接图标只打开图片 URL，均不会触发主体复制；Item 下方两个文字按钮消失。
13. 同一 URL 的并发或重复复制只下载一次，已缓存结果可被随后导出复用；失败后再次操作会重新请求。
14. 高级设置在重启后能恢复 4.x 上次成功获取的 URL/key/log 操作；3.x 显示缓存状态且不显示无意义的 key 操作。
15. 清除当前账号缓存不会删除或清空其他账号的缓存，当前账号界面会同步回到无预览状态。
